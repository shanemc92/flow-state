About
flow-state turns a process into two views of the same thing: a flowchart you can print or hand over, and a runbook with the detail each step needs. Build it on the build tab, fill in the detail on the runbook tab, and save the config to carry both.

Everything runs client side. There is no network call and no analytics. The config file is plain JSON, so it diffs and reviews like any other artefact.

The run tab is the other half. Import a config, start a run, and the tool walks the flow with you: it shows only the steps that are live right now, you pick the outcome at each decision, and every choice, note and skip is timestamped into a record you can export or print. Off-script actions get logged too rather than being lost. Imported processes and runs are kept in this browser separately from the flow you are building, so resetting the builder does not touch them.
